La página es pública, pero solo quien tenga un token de mi cuenta de GitHub puede publicar. El token se guarda únicamente en este navegador y viaja directo a la API de GitHub: no pasa por ningún otro servidor.

Sin token guardado.

Crear el token (una sola vez)

  1. En GitHub: Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Repository access: Only select repositories → elegí martin_ferreira.
  3. Permissions → Repository permissions → Contents: Read and write. Metadata queda en Read solo.
  4. Elegí un vencimiento (por ejemplo, 90 días), generá el token y pegalo en Mi cuenta.

Qué pasa al publicar

  1. El editor arma el Markdown con la estructura de la guía (Introducción, Investigación, Proceso, Resultados, Reflexión, Archivos, Atribución).
  2. Comprime las imágenes y las sube a docs/images/<sección>/<entrada>/.
  3. Agrega la página al menú en mkdocs.yml y hace un solo commit en la rama main.
  4. GitHub Actions reconstruye el sitio. Tarda uno o dos minutos; el avance se ve en Actions.

Armar página

  • Elegís elementos de la paleta (título, texto, imagen, carrete, galería, antes/después, ficha, tabla, línea de tiempo, resultado, nota, video, código, archivos, pieza 3D) y completás sus campos. Pieza 3D sube un archivo .stl y lo muestra en un visor para girarlo, acercarlo, verlo en alambre y descargarlo. Cada elemento se mueve con las flechas o se quita con ×.
  • Las fotos se arrastran dentro de cada elemento; el pie de foto se escribe debajo de cada una.
  • El elemento Archivos tiene dos caminos: subir el archivo al repositorio (queda en docs/files/; hasta 10 MB sin aviso, hasta 50 MB con confirmación) o agregar un enlace a Google Drive, YouTube u otro sitio. Para Drive: subir el archivo, Compartir → Cualquier persona con el enlace, copiar el enlace y pegarlo.
  • La vista previa de la derecha muestra la página tal como va a quedar. Publicar sube la página, las fotos y los archivos en un solo commit y la agrega al menú.
  • Cualquier página del sitio se puede abrir en el constructor: desde Armar página con "Abrir una página existente", o desde Markdown con "Abrir en Armar página". El Markdown se convierte en elementos (títulos, textos, carretes, galerías, fichas, tablas, resultados, notas, videos, código, piezas 3D, archivos) y al publicar se reemplaza la página.
  • En Markdown, "Insertar plantilla…" pega la estructura de una plantilla en el cursor, dentro de la página que tengas abierta.

Archivos

  • La pestaña Archivos muestra las carpetas de docs/files/ (archivos) y docs/images/ (fotos). Carpeta nueva crea una por módulo, por ejemplo mt02, en las dos a la vez.
  • Elegís una carpeta, arrastrás los archivos y Subir los manda en un solo commit. Las fotos se comprimen salvo que lo desactives; los archivos de más de 10 MB piden confirmación y más de 50 MB no entran.
  • Cada archivo tiene Copiar (el fragmento de Markdown: imagen, visor 3D o enlace) e Insertar, que lo pega en la página abierta en Markdown con la ruta correcta.
  • En la pestaña Markdown, el botón Materiales abre el mismo contenido sin cambiar de pestaña: elegís la carpeta del módulo y cada archivo ofrece sus formatos (imagen con pie, línea para carrete o galería, enlace, visor 3D). Armar borrador con todo crea una página nueva con todas las fotos en un carrete, las piezas 3D en su visor y los demás archivos como enlaces.
  • En Armar página, los elementos con fotos o piezas 3D tienen Elegir del repositorio para usar material ya subido sin volver a cargarlo.

Markdown

  • + Nueva desde Markdown: pegá o escribí el texto (por ejemplo, uno que te generó otra IA), mirá la vista previa con el estilo del sitio, elegí sección y posición en el menú, y guardá. El título se toma del primer #.
  • Ubicación: sección existente, nivel principal o sección nueva; y posición al principio, al final o después de una página concreta.
  • Ver como en el sitio abre la vista previa a pantalla completa con el ancho real de la página.

Editor de páginas

  • + Página nueva crea una página en la sección elegida a partir de una plantilla, y al guardar la agrega al menú.
  • La barra Formato aplica negrita, títulos, listas, enlaces y tablas al texto seleccionado. La barra Bloques inserta carrete, galería, comparación, ficha de datos, línea de tiempo, video y etiquetas de resultado. Si hay fotos cargadas, el carrete y la galería se arman con ellas.
  • La vista previa se actualiza sola mientras escribís, con los carretes funcionando. Se puede ver solo el texto, solo la vista previa, o las dos en paralelo. El botón ⤢ pone el editor a pantalla completa (Esc para salir).
  • Doble clic en la vista previa salta al texto que genera ese elemento: en Markdown selecciona la línea y la trae a la vista; en Armar página abre y enfoca el bloque.
  • Atajos: Ctrl+B negrita, Ctrl+I cursiva, Ctrl+K enlace, Ctrl+S guardar.

Sin token

Igual podés escribir la entrada, copiar el Markdown o descargar el .md y subirlo después desde Visual Studio Code, como hasta ahora.

Si algo no anda

  • 401 o 403 → el token venció o no tiene Contents: Read and write sobre este repositorio.
  • 409 o 422 → alguien (o vos, desde otra computadora) cambió el repositorio mientras editabas. Actualizá la lista y volvé a intentar.
  • La página no aparece → mirá Actions: si el build falló, el error suele ser una ruta de imagen o una línea mal indentada en mkdocs.yml. Se corrige desde Editar archivo.
