# Construcción de mi sitio web

Este sitio es mi bitácora de la **Especialización en Fabricación Digital e Innovación de UTEC**. Acá voy a compartir pruebas, dificultades y avances, vinculándolos con mi trabajo como docente de Física y referente STEM del Colegio Hans Christian Andersen.

También quiero profundizar en **fisicabit.com**, un proyecto que desarrollo con Pablo Godoy y que combina Física, placas micro:bit y recursos abiertos. Mi intención es ampliar el material para equipar laboratorios mediante fabricación digital, incluyendo diseños y piezas impresas en 3D.

## Primeros pasos y ayuda de la IA

Me apoyé en herramientas de inteligencia artificial para editar documentos, ordenar textos y pedir ayuda con algunos elementos visuales. Otro desafío fue contar mi trayectoria: elegir qué incluir y cómo relacionar mi trabajo cotidiano con este proyecto sin hacer una presentación demasiado larga.

Algunos pedidos que hice, resumidos para esta bitácora:

- **«Acortá el Markdown y mostrá dónde trabajo y qué hago en 3D».**
- **«Explicá qué hace fisicabit.com e incluí una práctica sencilla».**
- **«Prepará capturas para poner en la página».**
- **«Editá mi foto en blanco y negro».**
- **«Incluí que soy referente STEM en el Colegio Hans Christian Andersen».**

Estos son ejemplos de mis pedidos, no un registro completo ni una transcripción literal de todos los prompts. La IA me ayudó a avanzar, aunque todavía estoy aprendiendo cómo funcionan varias de las soluciones.

## Lo que me fue costando

**Agregar imágenes.** Tuve que aprender dónde guardar los archivos y cómo escribir sus rutas para que aparecieran en la página. Algo que parece sencillo terminó siendo parte del aprendizaje.

**Markdown.** Estoy aprendiendo a escribir títulos, enlaces, listas y bloques de código. Por eso armé una pequeña chuleta para tener a mano.

**Control de versiones.** Me costó entender el panel *Source Control* de Visual Studio Code y cómo se relaciona con Git y GitHub. También instalé Git Bash, aunque todavía necesito practicar para entender mejor cómo usarlo.

**Publicar.** Lograr que los cambios aparezcan en el sitio fue otro gran desafío. Todavía no tengo del todo claro el proceso, pero ver el enlace publicado y algunas partes funcionando fue un avance que me dejó muy contento.

## Trabajar desde varias computadoras

Durante el día alterno entre la computadora que llevo conmigo, la de casa y una Mac. Repetir la configuración del proyecto en cada equipo me consume tiempo.

Con ayuda de IA desarrollé un aplicativo pensado para preparar el entorno según la configuración inicial del proyecto y agilizar el trabajo entre equipos. La idea es dedicar menos tiempo a configurar y más a desarrollar el sitio.

## Mi chuleta de Markdown

| Quiero hacer… | Escribo… |
| --- | --- |
| Título | `# Título` |
| Subtítulo | `## Subtítulo` |
| Negrita | `**texto**` |
| Lista | `- Elemento` |
| Enlace | `[Fisicabit](https://fisicabit.com)` |
| Imagen | `![Descripción](images/foto.jpg)` |
| Archivo descargable | `[Descargar](archivos/archivo.zip)` |
| Código en una línea | `` `código` `` |

Para una imagen, primero guardo el archivo en la carpeta correspondiente y después escribo la ruta. El nombre, la extensión y las mayúsculas deben coincidir. La descripción explica qué muestra la imagen.

```markdown
![Sala STEM del Colegio Hans Christian Andersen](images/welcome/salastem.jpg)
```

Esta ruta es un ejemplo para una página ubicada junto a la carpeta `images`; si cambio la ubicación de la página, tengo que revisar la ruta.

**Para no confundirme:** Git guarda el historial; GitHub aloja el repositorio; Source Control es el panel desde el que gestiono cambios en VS Code; Git Bash permite usar comandos de Git y de terminal en Windows.

**Recordatorio:** guardar un archivo, hacer un commit y subirlo son pasos distintos. Que el sitio se publique después depende de cómo esté configurado el proyecto.

## Lo que viene

Más adelante quiero personalizar el **CSS**, tomando como referencia la estética de fisicabit.com. Voy a trabajar el contraste, la tipografía y el espaciado para lograr una lectura cómoda. También quiero explorar el uso de mayúsculas en títulos y opciones de visualización, revisando su accesibilidad antes de extenderlas a todo el texto.

El sitio sigue en construcción: quiero que también muestre ese proceso de aprender, probar y corregir.
